# 微信自动回复助手

监控微信白名单联系人，来消息时调用 LLM 以你的身份自动回复。**带图形界面**：改监控对象、换人设、填 API Key、管理聊天记录（查看/清空/导出）全部在界面里完成，配置改动即时生效。

## 两种运行方式

| 方式 | 适合 | 启动 |
|---|---|---|
| **图形界面应用**（推荐） | 日常使用、分发给别人 | 双击 `app.py`（需 Python）或打包好的 exe |
| 控制台调试 | 排查问题 | `python main.py`（`--check` 体检 / `--test-send` 链路自测） |

## 快速开始（图形界面）

1. **登录微信 PC 客户端**（窗口开着、最小化、托盘都可以）
2. 安装依赖：`pip install -r requirements.txt`，然后运行 `python app.py`
3. 【设置 → AI 接口】选厂商 → 粘贴 API Key → 选模型 → 保存
4. 【设置 → 监控对象】每行填一个好友昵称/备注名（必须和微信会话列表显示一致）→ 保存
5. 【设置 → 人设中心】选预设（猫娘/正经助理/毒舌损友/客服）或自由编辑 → 保存
6. 回到【状态】页点**启动监控**。关闭窗口只是缩到托盘，监控继续；托盘右键可退出
7. 不确定链路通不通：`python main.py --check` 体检、`--test-send` 发测试消息

## 打包成 Windows 应用（分发给别人）

```
python build_app.py
```

产物在 `dist/微信自动回复助手/`，把整个文件夹压缩发人即可。对方解压后：双击 `微信自动回复助手.exe` → 填自己的 API Key → 加监控对象 → 启动监控。

说明：产物约 245MB（含 OCR 模型）；未签名应用首次运行会有 SmartScreen 提示，点"更多信息→仍要运行"。构建脚本会优先保留已有应用目录中的配置；对外分发前请删除 `.env` 并重新填写自己的 Key。

## 技术路线（隐形截图 OCR 轮询 + 键盘自动化，兼容微信 4.1.13+）

不碰协议、不注入进程、不需要系统通知。每 20 秒把微信窗口以"屏幕外+不抢焦点"方式临时渲染并 PrintWindow 截图（用户全程不可见），OCR 读会话列表，检测白名单联系人的未读红点；触发后自动搜索联系人、校验、粘贴回复。

> 为什么不走系统通知：实测微信 4.x 的策略是**私聊消息不产生系统通知**（只亮红点），无论窗口状态如何也没有设置可改；只有群聊消息会弹通知。
>
> 为什么不是 wxauto 等 UI 自动化库：微信 4.1.13.12 起界面改为自绘 GPU 渲染，不向系统暴露控件树，所有 UIA 类库都读不到内容。

> ⚠️ **风险须知**：自动化操作微信违反《微信软件许可及服务协议》，封号风险无法降为零（护栏只能压低概率）；聊天内容会发送给你配置的云端 LLM 厂商。仅供个人助理用途，勿用于营销群发等场景。

## 两种回复模式（设置 → 高级选项 → 回复模式）

**多人轮询模式**（默认）：检测依赖未读红点 + 会话列表预览 → 回复后自动切到文件传输助手 → 下一条消息带红点再触发。适合监控多个人、或你不盯着微信的场景。限制：对方连发多条时只能看到最后一条。

**单聊常驻模式**：微信窗口停在唯一监控对象的聊天页面，**完全不依赖未读/已读状态或会话列表预览**，直接 OCR 聊天气泡，与已见气泡对比。新增的每条对方气泡都会单独结合上下文生成并发送回复，回复后不切离会话。对方/我方按**气泡底色**区分（对方白底、我方微信绿），换行消息自动合并；每次发送都通过搜索定位重新打开会话——实测只有这一步能让微信 4.x 激活聊天输入框，跳过它粘贴会静默失效。

单聊模式已知限制：只使用监控名单第一人；修改监控对象后程序会自动搜索并切换到新联系人，并对新会话重新建立气泡基线；窗口被最小化时回复瞬间会自动弹出。

配置和聊天状态采用临时文件写入后原子替换，避免界面保存配置的同时被监控线程读到半截文件。设置了静默时段时，多人模式会暂停触发但保留未读游标，时段结束后仍会处理该消息。

## 运行前提（硬性）

- 微信 PC 客户端保持登录运行（窗口开着、最小化、收进托盘都可以）
- **电脑不锁屏**（截图和键盘自动化都依赖活动桌面会话）
- **只能运行一个实例**：双开会导致两个助手抢鼠标、回复错位。重复启动会被 bot.lock 拒绝；想重启先关旧窗口（或任务管理器结束 python.exe / 微信自动回复助手.exe）
- 自动回复瞬间微信窗口会短暂出现在屏幕上（约 5 秒，发完自动收回）

## 内置安全机制

| 机制 | 说明 |
|---|---|
| 白名单 | 只处理监控名单里联系人的消息 |
| 未读判定 | 只在会话行有红点角标且预览变化时才回复；自己发的消息不会误触发 |
| 敏感词拦截 | 转账/红包/借钱/验证码等消息不自动回复，弹窗提醒你本人 |
| 发送前校验 | 点击搜索结果后 OCR 校验聊天标题是目标联系人，否则放弃 |
| 发送后核对 | 发送后 OCR 在聊天气泡里找刚发的内容，找不到就记警告 |
| 频率上限 | 单联系人每小时回复上限可在界面调整（0=不限） |
| 熔断 | 连续出错 5 次自动停止，弹窗告知 |

## 文件说明

- `app.py` —— 图形界面入口（打包目标）
- `main.py` —— 控制台入口（--check / --test-send / 无界面运行）
- `config.yaml` —— 监控名单、间隔、敏感词（界面修改后自动写回；热重载）
- `persona.md` —— 当前生效的人设（界面编辑后写回）
- `.env` —— LLM 的地址/Key/模型（不要外传）
- `wechat_bot/` —— 界面(app_gui)/控制器(controller)/托盘(tray)/检测(watcher)/回复(keys)/护栏(guard)/LLM(llm)/状态(state)/运行时(runtime)/人设预设(persona_presets)
- `logs/bot_日期.log` —— 审计日志（30 天自动清理）
- `state.json` —— 预览游标、对话记忆、回复记录，可删除重置
- `bot.lock` —— 单实例锁（运行时存在，进程退出自动释放）

## 已知限制

- 只支持**私聊**；群聊不回复
- 检测间隔 20 秒，回复总延迟约 30~60 秒（刻意放慢，行为更像人）
- 消息内容取自会话列表预览，超长消息会被截断（以"…"结尾）
- 监控对象的会话必须留在微信会话列表可见范围内（太久不聊被顶出列表就检测不到）
- 微信大版本更新可能改变界面布局，需重新校准
- 锁屏后截图和键盘自动化都不可用，解锁后监控自动恢复
